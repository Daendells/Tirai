# Detector evaluation

This folder measures how well the sensitive-number detector in `extension/shared/detect.js` works.

## What is measured

The detector looks for six types of sensitive text in chat messages: Indonesian ID numbers (nik), bank cards (card), bank accounts (account), one-time codes (otp), phone numbers (phone) and e-mail addresses (email). Each hit becomes a mask.

- Precision is the share of masks that were right.
- Recall is the share of sensitive items that got masked.
- F1 combines the two into one number.

A mask counts as right when it has the same type as a labelled item and covers at least 80% of the labelled span. Each labelled item can be matched by only one mask, and matching goes in order of position (see `score.js`). A mask with no match is a false positive (fp). A labelled item with no match is a miss (fn).

## How the sets were made

Dev set (`dev.jsonl`, 282 lines): written by the detector's author with a seeded generator, `make-dev.js`. It was used to tune the rules, so its scores are expected to be high.

Test set (`test.jsonl`, 200 lines): 200 synthetic messages generated by the seeded template script `make-test.py`. Its author only had the brief (`test-brief.md`) and never saw the detector code. The brief listed only the type definitions and the hard-negative categories (ordinary numbers that must not be masked). It was measured once on 2026-11-10 and the detector was not changed afterwards. 76 of the 200 messages have no sensitive item at all.

The test set comes from a script with fixed message templates, not free-form chat. Its hard-negative categories come from the same list the detector was designed around, so zero false positives here shows those categories are handled and says little about kinds of numbers nobody listed.

Run them with `node eval/run.js dev` and `node eval/run.js test`. Results are saved in `results-dev.json` and `results-test.json`.

In practice: on the blind set the detector masked none of the ordinary numbers (prices, quantities, dates, plate numbers and similar) in any of the 200 test messages. That includes all 76 messages that contain nothing sensitive. It missed 2 of 149 sensitive items. One was a 4-digit code written as "2FA code just came in: 2787" in an English message, which is close to the known "kode" limit below. The other was a 16-digit account number given as the new one ("pake yg ini ...") right after an old account number in the same message. The detector masked only the old one, and this is not one of the known limits. With 149 sensitive items, one miss changes recall by about 0.7 points.

## Known limits

- Landline numbers are not masked.
- A 4-digit code after the bare word "kode" is not masked.
- Text like "Pin lokasi ... 1234" can be masked by mistake.
- Real chats have typos, odd spacing and number formats that a template script does not produce, so real-world recall and precision are probably lower than these numbers.
- Both sets are small, so a few items move the percentages a lot. The test set is a spot check, not a guarantee.

All numbers in both sets are synthetic. No real person's data is used.
